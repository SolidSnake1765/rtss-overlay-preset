# Как подредактировать оверлей под себя

Оверлей — обычный файл RTSS `rtss-overlay-preset.ovl`, его можно менять во встроенном редакторе RTSS.

> **Перед правками** сохраните копию под своим именем (**Оверлеи → Сохранить как**, например `rtss-overlay-preset-my.ovl`).
> Повторный запуск `install.bat` пересобирает `rtss-overlay-preset.ovl` и затрёт ваши изменения в нём.

## Как открыть редактор

RTSS → **Setup** → вкладка **Плагины** (Plugins) → выделите **OverlayEditor.dll** → **Настроить** (Setup).
Колесо мыши — масштаб. Серые рамки вокруг каждого элемента видны только в редакторе, в игре их нет.

## Основное

Названия — как в русском интерфейсе RTSS, в скобках английские.

| Что хочу | Где |
|---|---|
| Сдвинуть элемент | перетащить мышью (включена привязка к сетке: **Вид → Привязка к сетке**) |
| Поменять текст, цвет, размер | двойной клик по слою → **Свойства слоя**: **Гипертекст**, **Пользовательский цвет текста**, **Размер текста, в процентах** |
| Поменять шрифт целиком | **Оверлеи → Редактировать** (Ctrl+Enter) → **Настройки создателя** (шрифт хранится в самом оверлее, пока включено **Запретить настройки пользователя**) |
| Убрать элемент | выделить слой → Delete |
| Добавить свой датчик | **Источники → Редактировать** (Ctrl+D) → добавить источник → провайдер **LibreHardwareMonitor** или **Internal HAL** → выбрать датчик; затем в гипертексте слоя написать `%Имя источника%` |
| Сохранить | **Оверлеи → Сохранить** (Ctrl+S) или **Сохранить как** |
| Поделиться | **Оверлеи → Экспорт** — файл `.ovx` со всеми картинками внутри |

## Как устроен текст слоёв

- `%CPU Package%` — значение источника данных с таким именем (список — меню **Источники**).
- `%CPU%`, `%GPU%`, `%RAM%`, `%Driver%` — встроенные макросы: модель процессора, видеокарты, объём памяти, драйвер NVIDIA.
- `<FR>`, `<FT>`, `<FRAVG>`, `<FR10L>`, `<FR01L>` — FPS, frametime, средний, 1% и 0.1% low.
- `<API>`, `<RES>` — графический API игры и разрешение.
- `<G=Имя источника,ширина,высота,отступ,мин,макс,флаги>` — график / полоска (так нарисованы полоски потоков).

## Цвет-предупреждение

Температуры и FPS меняют цвет по порогам. Это поле **Пользовательский цвет текста** вида

```
FFFFFF,,85,FFD040,85,95,FF4848,95,(CPU Package,0)
```

— белый до 85, жёлтый 85–95, красный от 95, по источнику `CPU Package`. Поменяйте числа — поменяются пороги.

| Датчик | Жёлтый | Красный | Почему |
|---|---|---|---|
| Процессор | 85 °C | 95 °C | Intel 12–14 gen: предел 100 °C; AMD Ryzen 7000/9000: штатно работает до 95 °C |
| Видеокарта (ядро) | 80 °C | 88 °C | частоты начинают снижаться примерно с 83 °C |
| Hot Spot | NVIDIA/Intel 95, AMD 100 °C | NVIDIA/Intel 105, AMD 110 °C | у AMD предел Hot Spot — 110 °C |
| Видеопамять | NVIDIA 95, AMD/Intel 90 °C | NVIDIA 105, AMD/Intel 100 °C | GDDR6X — ~105–110 °C, GDDR6 — 100 °C |
| Модули ОЗУ | 50 °C | 60 °C | выше разогнанная память начинает сбоить |
| FPS | < 60 | < 30 | |

## Компактная строка

Компактная строка — два последних слоя файла: `compact` и его копия `compact.bottom` (о ней ниже); вся строка в поле
**Текст** гипертекстом RTSS:
`<C=RRGGBB>` — цвет, `<S=48>…<S=80>` — мелкие надстрочные единицы, `<I=6,7,0,0,32,32>` / `<I=6,7,32,0,32,32>` — стрелки
↓ и ↑ из `rtss-overlay-preset-icons.png`, `<G=…>` — график FPS и полоски потоков прямо в тексте,
`<IF IsFG>…<ELSE>…<IF>` — вариант строки при генерации кадров. График FPS — `<G=FpsSec,…>`: точка на каждое обновление оверлея (500 мс), около 40 с истории. Полоски потоков жёлтые от 70 % и красные от 90 % загрузки (источники `Warm<n>`, `Hot<n>`). Цвета блоков: FPS `E8836B`, CPU `E5C35C`, GPU `7DC75A`,
RAM `B49DDB`. Чтобы убрать часть строки, удалите её кусок из текста; чтобы переместить строку — сдвиньте слой.
Подложка: у слоя задана высота 11 и выравнивание по центру, а последний тег строки `<I=8,7,0,0,2,2>` — невидимая
вставка (прозрачный угол картинки стрелок): без неё RTSS делает подложку короче текста и последнее «GB» вылезает.
Нижняя копия: RTSS прижимает к краю экрана рамку всего оверлея, а OverlayEditor передаёт ему и размеры скрытых слоёв
большого вида — рамка всегда высотой с большой вид. Когда оверлей у нижнего края (`PositionY` в профиле RTSS
отрицательная — датчик `/overlay-preset/osd/data/1`), показывается `compact.bottom` у низа рамки (источники `OsdBottom`,
`CompactTop`, `CompactBottom`). Меняя текст строки, меняйте его в обоих слоях.

## Как устроено переключение видов

**Оба вида — в одном файле.** В `rtss-overlay-preset.ovl` лежат и все слои большого оверлея, и слой компактной строки
(последний, `compact`). У каждого слоя есть **источник видимости**: слой рисуется, только когда этот источник
не равен нулю.

**Решают два служебных источника** (меню **Источники**):

| Источник | Формула | Равен 1, когда |
|---|---|---|
| `StyleFull` | `(key(0x91) & 1) == 0` | нажатий чётное число (0, 2, 4…) — виден большой оверлей |
| `StyleCompact` | `(key(0x91) & 1) != 0` | нажатий нечётное число (1, 3, 5…) — видна компактная строка |

`key(0x91)` — встроенная функция RTSS: счётчик нажатий клавиши с кодом `0x91` (Scroll Lock). Считает плагин
**HotkeyHandler** — он должен быть включён. `& 1` — последний бит счётчика, то есть «чётное / нечётное».
Счётчик видит одну клавишу и не видит Ctrl/Alt, поэтому сочетание тут не назначить. После перезапуска RTSS счётчик
снова 0 — показан основной вид.

**Слои привязаны к ним:** у слоёв большого вида видимость `StyleFull`, у компактной строки — `StyleCompact`.
Ячейки температур и раньше прятались, если датчик молчит, поэтому у них свои источники `Full0`, `Full1`… — копия
датчика с формулой `(StyleFull) ? (x) : 0`: в большом виде значение датчика, в компактном 0.

### Как поменять

- **Проще всего** — снова запустить `install.bat`: в окне горячих клавиш пункт «Переключить вид оверлея».
- **Другая клавиша вручную:** в формулах `StyleFull` и `StyleCompact` замените `0x91` на код нужной клавиши:

  | Клавиша | Код | | Клавиша | Код |
  |---|---|---|---|---|
  | Scroll Lock | `0x91` | | Insert | `0x2D` |
  | Pause | `0x13` | | Home | `0x24` |
  | F12 | `0x7B` | | Num 0 … Num 9 | `0x60` … `0x69` |

  Остальные — в таблице Microsoft
  [Virtual-Key Codes](https://learn.microsoft.com/windows/win32/inputdev/virtual-key-codes).
- **Основным сделать компактный вид:** поменяйте местами `== 0` и `!= 0` в этих двух формулах
  (или выберите его основным при установке).
- **Свой слой** только для одного вида: в его свойствах укажите источник видимости `StyleFull` или `StyleCompact`.

> Повторный `install.bat` пересобирает файл и затирает ручные правки — сохраните свой вариант под другим именем.

## Present Mode

Слой `fps.res` (строка с разрешением): `<RES>` и режим вывода кадров. Источник `PresentMode` — счётчик PresentMon
(входит в RTSS) с кодом режима `PM_PRESENT_MODE` (`SDK\Include\PresentMon\PresentMonAPI.h` в папке RTSS):

| Код | Режим PresentMon | Источник | В оверлее |
|---|---|---|---|
| 3 | Hardware: Independent Flip | `PmIFlip` | зелёный `iFlip` |
| 8 | Hardware Composed: Independent Flip (аппаратный слой MPO) | `PmMpo` | зелёный `iFlip MPO` |
| 4 | Composed: Flip (через DWM) | `PmComposed` | жёлтый `Composed` |
| 5, 6 | Composed: Copy with GPU / CPU GDI | `PmCopy` | красный `Composed Copy` |
| 1 | Hardware: Legacy Flip (эксклюзивный полный экран) | `PmLegacyFlip` | зелёный `Legacy Flip` |
| 2 | Hardware: Legacy Copy to front buffer | `PmLegacyCopy` | зелёный `Legacy Copy` |

Пока режим неизвестен (0 — например, нет игры), строка показывает только разрешение. Варианты идут цепочкой
`<IF PmIFlip>…<IF PmMpo>…<IF>`: блоки `<IF>` не вкладываются, каждый закрывает предыдущий. Что значат режимы — в README
(раздел Present Mode) и в гайде [«Presentation Model в Windows»](https://andrilaz.github.io/presentation-model) (автор Andrilaz).

## Генерация кадров

С генерацией кадров RTSS считает и сгенерированные кадры. Источники (меню **Источники**):

| Источник | Формула | Что это |
|---|---|---|
| `FrameratePresented`, `FramerateDisplayed` | PresentMon | кадров в секунду от игры и на экране |
| `TotalFPS` | FPS самого RTSS (`RtssFps`, датчик `/overlay-preset/fps/data/9`, как `<FR>`); при драйверной генерации — больший из двух PresentMon (`PmFps`) | FPS с генерацией (при генерации FSR через OptiScaler PresentMon насчитывал на ~6 % меньше RTSS и Steam) |
| `DrvFG` | `FramerateDisplayed >= FrameratePresented * 1.5` | драйверная генерация (AFMF, Smooth Motion) |
| `FgLib` | датчик `/overlay-preset/fg/data/0` | 1 — у игры есть библиотека генерации |
| `FgRhythm` | датчик `/overlay-preset/fgr/data/0` | ритм: средний скачок времени GPU к соседнему кадру / среднее время |
| `FgMul` | датчик `/overlay-preset/fgr/data/1` | кратность: через сколько кадров повторяется рисунок (2…8), 0 — не повторяется |
| `FgN` | датчик `/overlay-preset/fgr/data/2` | кратность, чаще всего встречавшаяся за 5 с — для реального FPS |
| `GameFG` | `FgLib` и `FgRhythm >= 0.25` и `FgMul >= 2` | генерация внутри игры |
| `IsFG` | `swavg(FgRaw,10) >= 0.6` | 1 — генерация была большую часть последних 5 с (10 обновлений по 500 мс) |
| `IsFGApprox` | генерация не драйверная | показывать `≈` |
| `NativeFPS` | `DrvFG ? FrameratePresented : TotalFPS / FgN` (`FgN` меньше 2 — делим на 2) | реальный FPS игры |
| `FgShowN` | `DrvFG ? round(FramerateDisplayed / FrameratePresented) : FgN` | кратность в надписи `FG≈×4` (значок `×` — `<I=6,7,96,0,32,32>`) |

Ритм и кратность считает `Exporter.dll` (`src\Exporter\FrameRhythm.cs`) по последним ~240 кадрам игры из общей памяти
PresentMon (`PMDPSharedMemory`, формат — `SDK\Include\PMDPSharedMemory.h` в папке RTSS): у каждого кадра берётся время
работы видеокарты (`GPUBusy`), D(k) — средний модуль разницы с кадром k назад; ритм = D(1) / среднее, кратность —
наименьшее k из 2…8, при котором D(k) не больше половины D(1). Формулами оверлея это не посчитать: PresentMon отдаёт
кадры пачками, и `buf()` в формуле видит только конец пачки — прежняя версия на ×3 ошибалась в двух случаях из трёх.

Замеры (Witcher 3 + OptiScaler, FSR 3.1 FG, RTX 3080 Ti, 26.10.2026), по 16–40 замеров на режим:

| Режим | Ритм | Кратность | Реальный FPS / итоговый |
|---|---|---|---|
| без генерации | 0.06–0.08 | 0 | — |
| ×2 | 1.6–2.1 | 2 | ~67 / ~134 |
| ×3 | 1.61–1.64 | 3 | ~78 / ~235 |
| ×4 | 1.49–1.53 | 4 | ~73 / ~293 |
| ×5 | 1.39–1.46 | 5 | ~66 / ~330 |
| ×6 | 1.33–1.37 | 6 (OptiScaler иногда вставляет 4 кадра вместо 5) | ~61 / ~370 |

Порог ритма `0.25` — в формуле `GameFG`. В меню игры ритм тонет в шуме и признак не держится — это нормально.

В тексте слоёв: `<IF IsFG>…<ELSE>…<IF>`; `<IF>` не вкладываются (каждый следующий закрывает предыдущий),
поэтому `≈` выводится отдельным блоком `<IF IsFGApprox><I=6,7,64,0,32,32>` — значком из
`rtss-overlay-preset-icons.png`: символ `~` мелким шрифтом RTSS рисует плоской чёрточкой, похожей на минус.

## Данные, которые добавляет этот пресет

Датчики и оверлей обновляются каждые 500 мс: `RefreshPeriod=500` в файле оверлея, а таймер LHMDataProvider
(в RTSS он жёстко 1000 мс) Exporter.dll переставляет на 500 мс при каждом вызове (`src\Exporter\UpdateTimer.cs`).
Графики добавляют точку на каждое обновление, поэтому их история — ширина графика × 0.5 с.

`Exporter.dll` из этого пресета отдаёт в RTSS (провайдер LibreHardwareMonitor) дополнительные блоки
**Memory Timings** и **Frame Generation** — их можно использовать в своих слоях:

| ID источника | Что |
|---|---|
| `/overlay-preset/memory/clock/0` | эффективная частота памяти, MT/s |
| `/overlay-preset/memory/timing/tcl`, `trcd`, `trp`, `tras`, `trc`, `trfc` | основные тайминги |
| `/overlay-preset/memory/timing/tcwl`, `trefi`, `cr` | tCWL, tREFI, Command Rate (1/2) |
| `/overlay-preset/memory/data/1` | Gear (Intel) |
| `/overlay-preset/fps/data/0` | FPS игры на переднем плане за последние полсекунды — по буферу кадров из общей памяти RTSS (тот же расчёт, что у самого RTSS); по нему строится плавный график FPS компактной строки |
| `/overlay-preset/fps/data/1` | самый долгий кадр за последние полсекунды, мс — из буфера кадров RTSS (в оверлее сейчас не используется) |
| `/overlay-preset/fps/data/2`, `3`, `4`, `8` | AVG, 1% low, 0.1% low и максимум (лучшая секунда) по настоящим кадрам: времена кадров RTSS, сложенные по кратности генерации (`NativeStats.cs`); правила как у RTSS — «низы» в режиме integral (кадр, на котором сумма самых долгих кадров достигает 1% / 0.1% всего времени) или percentile по настройке RTSS `PercentileCalc`; сброс вместе со статистикой RTSS |
| `/overlay-preset/fps/data/5`, `6`, `7` | родные AVG, 1% low, 0.1% low RTSS (для цвета-предупреждения, когда генерации нет) |
| `/overlay-preset/osd/data/0`, `data/1` | положение оверлея на экране — `PositionX`, `PositionY` из профиля RTSS (профиль игры, если в нём задано, иначе Global); отрицательное — от правого / нижнего края |
| `/overlay-preset/fg/data/1` | как найдена библиотека (для отладочных строк `install-debug.bat`): 1 — загруженный модуль, 2 — DLL в папке игры, 3 — FSR 3 внутри exe, 0 — не найдена; +10 — список модулей закрыт (античит) |
| `/overlay-preset/fgr/data/0`, `1`, `2` | ритм генерации кадров, кратность (2…8, 0 — нет) и кратность за 5 с — по кадрам из общей памяти PresentMon |
| `/overlay-preset/fg/data/0` | 1 — у игры на переднем плане есть библиотека генерации кадров (DLSS-G, FSR, XeSS-FG или встроенный FSR 3); результат проверки exe кэшируется в `%ProgramData%\RTSS-Overlay-Preset\fg-cache.txt` |

Тайминги читаются напрямую из контроллера памяти: Intel Core 6–14 поколения, AMD Ryzen (Zen 2–5).
На остальных процессорах — только частота.
